## ทำไมลูกค้าต้องใช้ (ตัวเลขที่วัดจริง)

| ประเด็น | ก่อน | หลัง |
|---|---|---|
| ความกว้างแถบเลือกวัน | 1,104px ในจอ 390px ปัดราว 2 ครั้งจึงเห็น 15 วัน | เห็นทีละ 5 วัน มีปุ่มถัดไป/ก่อนหน้า |
| ปุ่มวันที่บอกจำนวนเวลาว่าง | 0 จาก 15 ปุ่ม (มีแค่ Closed/Full) | ทุกปุ่ม (เช่น 3 / 10 / 8 / 11 free) |
| เห็นเวลาที่จองได้ตอนเข้าหน้า | ไม่เห็น ต้องกดเลือกวันก่อน | เห็นทันที (เลือกวันนี้ไว้ให้) |
| ไปวันไกลสุดที่จองได้ | ปัดไปสุดแถบ แล้วแตะ | เปิดปฏิทินเดือน แล้วแตะ วันนอกช่วงกดไม่ได้ |
| ฟอร์มกรอกไม่ครบ | ข้อความใต้แต่ละช่อง | มีกล่องสรุปด้านบน + เครื่องหมาย * |
| ปฏิทินเจ้าของบนมือถือ | ตาราง 840px ในพื้นที่ 356px เห็น 2.5 จาก 7 วัน | รายการทีละวัน ไม่เลื่อนข้าง |

## ข้อจำกัดที่ต้องรู้
- **ไม่มีการทดสอบกับผู้ใช้จริง:** "ใช้ง่ายขึ้น" มาจากภาพและการวัดโครงสร้าง ไม่ใช่เวลาที่ใช้จริงหรืออัตราจองสำเร็จ
- **จำนวนการแตะไม่ได้ลดลง** ในกรณีไปวันไกล (ก่อน ปัด 2 + แตะ 1, หลัง แตะ 3) ประโยชน์อยู่ที่การเห็นขอบเขตและกันเลือกผิด
- **ผลของข้อ 3 เล็กที่สุด:** ฟอร์มมีแค่ 2 ช่องบังคับ
- **ตรวจเฉพาะ:** Chromium (Playwright) ที่ 390px ไม่ได้ดู Safari/Firefox, จออื่น (768px, 1440px), หรือ screen reader
- **ไม่ได้ให้ผู้ตรวจอิสระเปิดดูภาพ:** ตรวจเองรอบเดียว
- ภาพ "ก่อน" เป็นเวอร์ชันของเราเอง ไม่ใช่ UI ของแอปอื่น
